# Форма — студия редакционных SVG-иллюстраций

«Форма» собирает иллюстрации к материалам из настоящих векторных объектов библиотеки Figma: книга, телефон, пазлы, монета, наушники, лампа, букет, кошелёк, папка, ручка.

Работать можно двумя способами:

- **по заголовку**: опишите тему, и приложение само подберёт подходящие объекты и скомпонует их;
- **по названиям**: перечислите нужные объекты.

Готовую композицию можно доработать в небольшом векторном редакторе и экспортировать в самостоятельный SVG, который выглядит так же, как превью.

Приложение работает целиком в браузере: без сервера, без ключей и без обращений к внешним сервисам.

---

## Быстрый старт

Нужен Node.js 22.12 или новее. Сборка проверена на Node.js 26.7 и npm 11.

```bash
npm ci
npm run dev        # http://localhost:5173
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер Vite; при изменении `public/assets` страница перезагружается |
| `npm run build` | проверка типов + production-сборка в `dist/` (относительные пути, можно открыть с любого статического хостинга) |
| `npm run preview` | локальный просмотр собранного `dist/` |
| `npm start` | сборка + сервер `server/index.mjs` на http://localhost:8787: раздаёт `dist/` и включает подбор с ИИ, если задан ключ |
| `npm run server` | только сервер (рядом с `npm run dev` запросы `/api` проксируются на него) |
| `npm test` | все модульные тесты (Vitest) |
| `npm run typecheck` | строгая проверка TypeScript без сборки |
| `npm run check` | typecheck + тесты + сборка: одна команда для проверки перед сдачей |

В архиве для сдачи есть готовая папка `dist/`. Запустить её можно локально с Python 3.

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:4173/`.

Так редактор работает полностью, но объекты по заголовку подбирает только встроенный словарь. Чтобы включить подбор с ИИ, скопируйте `.env.example` в `.env.local`, впишите адрес и ключ OpenAI-совместимого API и запустите `npm start`. Ключ остаётся на сервере и в браузер не попадает.

При первом запуске открывается пример «Знания по кусочкам». Редактор подбирает книгу и пазлы, а на обложке оставляет место под заголовок. После этого состояние живёт в черновике браузера (`localStorage`). Чтобы начать с чистого листа, нажмите «Новый».

## Два сценария

### 1. По заголовку

Введите заголовок или метафору, например «Финансовая грамотность: как копить с первой зарплаты», и нажмите «Собрать композицию» (`⌘/Ctrl + Enter`).

Базовый анализ детерминированный и работает без сети:

1. **Нормализация.** Регистр, `ё → е`, пунктуация, дефисы, числа («8 Марта»).
2. **Стемминг.** Русский стеммер Snowball (Porter), поэтому «книги», «книгой» и «книг» дают один стем. Короткие стемы, которые совпадают с обычными словами («цвет» = цвет и цветы), сверяются по точным словоформам.
3. **Словарь.** Названия и другие названия объектов, синонимы («деньги» → монета) и темы («Деньги и финансы», «Учёба», «Праздник и подарки»…). У каждой темы есть веса связи с объектами. Фразы («день рождения», «8 марта») проверяются раньше отдельных слов.
4. **Отрицание.** «без», «не» и «кроме» исключают объект: «смартфон без наушников» даст телефон без наушников.
5. **Опечатки.** Расстояние Дамерау — Левенштейна с порогом по длине слова. Такое совпадение помечается как слабое и показывается с кнопкой «Заменить на …».
6. **Отбор.** Берутся до трёх объектов с достаточной силой совпадения, отсортированные по весу. Если опереться не на что, собирается нейтральная композиция с честным предупреждением и кнопками-примерами.

**Подбор с ИИ (если сервер запущен с ключом).** Каждый заголовок уходит в языковую модель вместе со списком id каталога. Модель возвращает 2–3 главных предмета, которые вместе передают метафору, фоновый предмет для обстановки и одно предложение с объяснением. Предметы, в которых словарь уверен, остаются в сцене первыми; исключённые через «без» не возвращаются; неизвестные id отбрасываются. Если основная модель не отвечает за 8 секунд, запрос уходит в резервную. При ошибке остаётся результат словаря, который тоже всегда даёт минимум два предмета. Модель только выбирает из каталога: она не видит и не меняет SVG.

Под кнопкой показывается толкование:

- какие объекты выбраны и почему: каждая причина цитирует слово из заголовка;
- сила совпадения;
- темы;
- исключённые и нераспознанные слова;
- подсказки с действиями: исправить опечатку, убрать слабый объект, попробовать пример.

### 2. По названиям

Перечислите объекты: «книга, 2 монеты + наушники». Разделители: запятая, `;`, перевод строки, `+`, «и», «плюс».

- Количество задаётся так: «2 монеты», «две монеты», «монета ×2», «x3». Максимум 4 экземпляра одного объекта и 8 объектов в композиции.
- Нумерация списка не считается количеством: в «1) книга» и «2) монета» (так же «(1)», «[1]», «1:», «1-», «#1», «а)») числа игнорируются. Число без знака («2 монеты») остаётся количеством.
- Падежи и множественное число распознаются: «наушниками», «ручки».
- Кнопка исправления меняет именно то слово, к которому относится подсказка. Если «ламба» написано дважды, правится то вхождение, рядом с которым нажата кнопка.
- У каждой строки свой статус:
  - **найдено**;
  - **похоже на…**: опечатка, объект добавлен с предупреждением и кнопкой «Исправить»;
  - **не найдено**: с ближайшей подсказкой, например «деньги» → «Заменить на „Монета“»;
  - **нет в библиотеке**: объект известен, но файлов нет.

### Примеры

| «Набор для учёбы» | названия | Квадрат, «Иллюстрация», S-детализация, плоскость и фоновый предмет | Мята |

## Редактор

**Добавление объектов.** Кликните мотив в каталоге (или нажмите `Enter`/`Space`) либо перетащите его на холст. Новый объект получает общий масштаб композиции.

**Выделение и перемещение.**

- Клик по объекту выделяет его. Срабатывает верхний под курсором.
- Перетаскивание двигает объект, с `Shift` движение идёт по одной оси, `Esc` во время перетаскивания отменяет жест.
- Каждый объект доступен по `Tab`.

**Поворот.** Ручка над рамкой выделения поворачивает объект, с `Shift` шаг 15°. Можно поворачивать и клавишами.

**Инспектор.** Точные X, Y и поворот: стрелки дают ±1, с `Shift` ±10. Там же:

- реальный файл, которым нарисован объект, и пометка «замена», если использован ближайший вариант;
- кнопки «дублировать», «выше», «ниже», «наверх», «вниз», «скрыть», «удалить».

**Слои.** Список идёт сверху вниз, как в Figma. Стрелки выбирают слой, `Alt + ↑/↓` меняют порядок, `Delete` удаляет, `Space` скрывает слой.

**Отмена и повтор.** Перетаскивание — один шаг истории. Серия сдвигов стрелками тоже склеивается в один шаг. Храним до 100 шагов.

**Черновик.** Автосохранение в `localStorage` идёт через 400 мс после изменения и при закрытии вкладки. Перед восстановлением черновик проверяется. Если он повреждён, открывается новый документ с предупреждением.

### Горячие клавиши

| Действие | Клавиши |
| --- | --- |
| Отменить / повторить | `⌘Z` / `⇧⌘Z` (`Ctrl+Z` / `Ctrl+Y`) |
| Дублировать | `⌘D` |
| Удалить | `Delete` / `Backspace` |
| Сдвинуть на 1 / 10 единиц | стрелки / `Shift` + стрелки |
| Повернуть на 1° / 15° | `[` `]` / `Shift` + `[` `]` |
| Слой выше / ниже | `⌘]` / `⌘[` |
| На передний / задний план | `⇧⌘]` / `⇧⌘[` |
| Экспорт SVG | `⌘E` |
| Собрать композицию | `⌘↵` в поле задания |
| Снять выделение | `Esc` |

Клавиши работают и в русской раскладке, потому что используется физическая клавиша. Полный список открывается кнопкой «Клавиши» в строке состояния.

### Параметры холста

**Верхняя панель:**

- **Формат:** квадрат 1080×1080, портрет 1080×1350 (4:5), обложка 1200×630. При смене формата композиция пересобирается одним шагом истории.
- **Детализация S/L:** упрощённые или подробные файлы, независимо от формата. Видимый размер и положение объектов сохраняются, потому что размер слоя хранится в единицах артборда.
- **Компоновка:**
  - **«Иллюстрация»**: сцена на весь кадр по правилам референсов из Figma (см. «Правила раскладки»);
  - **«С заголовком»**: та же сцена, но с зоной под заголовок. На горизонтальных форматах зона слева, на вертикальных и квадратных — сверху; сцена уходит за остальные края кадра.
- **«Перекомпоновать»**: заново раскладывает текущие объекты.

**Нижняя панель:**

- **Цвет:**
  - «Цветной»: основные цветные файлы `main`;
  - «Монохром»: вторичные монохромные файлы `background`.
- **«Плоскость»**: фоновая плоскость палитры (`plane-*.svg`). Масштабируется равномерно и заполняет артборд с обрезкой по центру, без искажений.
- **«Фон»**: фоновый предмет — *другой* объект библиотеки в контурном варианте (`background`), в общем масштабе, в свободном углу кадра за сценой и обрезанный им: ваза за наушниками, лампа за кошельком, книга за пазлом. Так устроены фоновые объекты в референсах. Предмет выбирает ИИ по смыслу заголовка, без ИИ — таблица соответствий. Фон остаётся второстепенным: видимая часть не больше трети кадра, под объектами он не лежит. Если такого места нет, фона нет, как в референсах «только с главными объектами». «Собрать» включает плоскость и фон; их можно выключить.
- **«Заголовок»**: показывает текст в зоне заголовка. Это направляющая превью, в экспорт она не попадает.

### Правила раскладки

Правила взяты из листов референсов в Figma («Варианты композиций на разных форматах»).

- **Общий масштаб.** Он один для всех объектов и фонового предмета, поэтому относительные пропорции рисунков Figma сохраняются: монета меньше книги, как в исходнике. Неравномерного масштабирования нет.
- **Натуральный размер.** Библиотека нарисована в едином масштабе, и референсы показывают предметы близко к нему. Сцена не увеличивается больше чем в 1,3 раза от натурального размера (на кадре 1080 px, S-файлы вдвое мельче L), поэтому одинокая монета не раздувается до размера книги.
- **Без поворотов.** Рисунки изометрические: любой автоматический поворот ломает сетку. Повернуть объект вручную можно.
- **Диагональ и стопки.** Предпочитаются ярусные раскладки по изометрической диагонали. Мелкие предметы ложатся на плоские (телефон на книгу, пазл на книгу, кошелёк на папку).
- **Обрезка кадром.** Если сзади плоский большой предмет (книга, папка), сцена крупнее кадра и он уходит за край: в кадре остаётся не меньше 62 % по каждой оси. Передние объекты могут касаться края, но остаются в кадре минимум на 90 %. Компактные сцены (кошелёк с монетой) остаются целыми и оставляют место фону.
- **Габариты.** Раскладка опирается на реальные границы геометрии из путей, трансформаций, обводок и `clipPath`, а не только на `viewBox`.
- **Выбор варианта.** Сравниваются ряд, ярусы, колонка и «на поверхности». Побеждает самый крупный с учётом бонуса за диагональ и стопку, а варианты, где объект закрыт больше чем наполовину, сильно штрафуются.
- **Гарантии** (проверяются тестами):
  - каждый объект виден минимум на 60 % по каждой оси;
  - в режиме «С заголовком» ни объект, ни фоновый предмет не заходят в зону заголовка; если фону негде встать, его нет;
  - масштаб общий, поворотов нет;
  - результат детерминирован.

## Палитры

**Встроенные** — три палитры из Figma с точными свотчами из `public/assets/source-manifest.json`: «Сирень» (исходная разметка объектов), «Персик» и «Мята». Палитра переключается мгновенно и меняет объекты, фоновый предмет и плоскость.

**Как перекрашивается рисунок.** Каждый цвет исходного SVG сопоставляется с ролью по точному свотчу исходной палитры. Объекты нарисованы в «Сирени», а каждая плоскость — в своей палитре. Затем роль заменяется цветом активной палитры. Перекраска всегда идёт от исходного файла, а не от уже перекрашенного. Неизвестный цвет относится к ближайшему свотчу в OKLab и сохраняет своё смещение от него.

### Схема палитры `forma.palette/v1`

Схема с описанием ролей видна в интерфейсе: «Палитра → Роли цвета» и в диалоге «Импортировать палитру…».

| Роль | Название | Где используется | Обязательна |
| --- | --- | --- | --- |
| `paper` | Бумага | Цвет артборда, когда плоскость выключена | нет (по умолчанию `#ffffff`) |
| `tint` | Светлый фон | Заливки фоновых вариантов и плоскости | да |
| `tone` | Средний тон | Средние тона плоскости и фоновых вариантов | да |
| `deep` | Глубокий тон | Линии фоновых вариантов, акцентные плоскости | да |
| `ink` | Контур | Линии и тени объектов | да |
| `highlight` | Блик | Тёплый акцент: блики и яркие детали | да |
| `accent` | Акцент | Главный цветовой акцент объектов | да |
| `accentSoft` | Мягкий акцент | Приглушённая версия акцента | да |
| `light` | Белый | Блики и светлые детали | да |

```json
{
  "schema": "forma.palette/v1",
  "name": "Моя палитра",
  "plane": "lavender",
  "colors": {
    "paper": "#ffffff",
    "tint": "#d7cdf5", "tone": "#aa9bf0", "deep": "#7864d7", "ink": "#181817",
    "highlight": "#f9ecb0", "accent": "#f9a3aa", "accentSoft": "#ffe3e1", "light": "#ffffff"
  }
}
```

**Поля:**

- `name` — обязательное, от 1 до 40 символов;
- `id` — необязательный slug. Если его нет, он берётся из транслитерации названия и делается уникальным;
- `plane` — форма фоновой плоскости: `lavender`, `peach` или `mint`;
- `schema` — необязательное, но если указано, то только `forma.palette/v1`.

Цвета записываются в форматах `#RGB` или `#RRGGBB`.

**Импорт безопасен:**

- JSON больше 20 КБ отклоняется ещё до разбора;
- используется только `JSON.parse`, никакого `eval`;
- ключи `__proto__`, `constructor` и `prototype` отбрасываются, объекты собираются заново;
- текст пользователя выводится только как текст React.

**Ошибки** собираются все сразу, с путями (`colors.accent — ожидается цвет в формате #RRGGBB, получено «violet»`). У синтаксических ошибок указаны строка и столбец. Неизвестные ключи и низкий контраст контура выводятся как предупреждения. Список ошибок озвучивается (`role="alert"`) и получает фокус.

Импортированные палитры хранятся в `localStorage` и при загрузке проверяются заново. Если браузер отказывает в записи, редактор сообщает, что изменение действует только в текущей вкладке.

## Экспорт SVG

Кнопки «Экспорт SVG» (`⌘E`) и «Копировать SVG» строят документ теми же функциями, что и превью (`src/export/render.ts`). Атрибуты групп, трансформации и разметка экземпляров совпадают байт в байт. Это проверяется тестом и попиксельным сравнением в браузере: средняя разница 0.

**Когда экспорт доступен.** Обе кнопки и `⌘E` задают один и тот же вопрос (`hasExportableContent` в `src/export/render.ts`): есть ли в файле что-то кроме бумаги, то есть видимый объект с файлом или включённая плоскость палитры. Если все слои скрыты и плоскости нет, экспорт и копирование отключены. Если плоскость включена, а слоёв нет, они доступны.

**Название файла и `<title>`.** Если задан заголовок, берётся он (направляющая заголовка в SVG не рисуется, это только метаданные). Иначе берутся названия видимых объектов по рангу. Скрытые объекты и фоновый предмет в название не попадают. Если названия нет, `<title>` будет «Форма», а файл `forma-illustration-<ширина>x<высота>.svg`.

**Структура файла:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<svg xmlns="http://www.w3.org/2000/svg" [xmlns:xlink="…" — только если нужен] width="1200" height="630" viewBox="0 0 1200 630">
  <title>Знания по кусочкам</title>
  <desc>Создано в «Форме» · 1200 × 630 · палитра «Сирень»</desc>
  <rect id="paper" …/>
  <g id="plane" data-forma-role="plane" transform="…">…</g>
  <g id="artwork">
    <g id="book-1" data-forma-motif="book" data-forma-role="object" transform="translate(…) rotate(…) scale(…) translate(…)">…</g>
  </g>
</svg>
```

**Устройство:**

- **Группы.** Каждый объект — отдельная редактируемая группа с понятным id (`book-1`, `coin-2`, `book-background-1`). В Figma и Illustrator они видны как слои.
- **Локальные id.** Все id внутри экземпляра получают префикс группы (`book-1__clip0`). Ссылки `url(#…)`, `href` и `xlink:href` переписываются, поэтому два экземпляра одного файла не конфликтуют. Тесты проверяют, что висячих ссылок и дубликатов нет.
- **Чистота.** Растра, скриптов, `foreignObject` и внешних ссылок в файле нет. Вся геометрия векторная, исходные пути не меняются, меняются только цвета.
- **Текст.** Символы, недопустимые в XML 1.0, из пользовательского текста (заголовка) удаляются.

## Ассеты

Файлы лежат в `public/assets/` и только читаются. Подробности в [`ASSET-CONTRACT.md`](ASSET-CONTRACT.md) и [`ASSET-NOTES.md`](ASSET-NOTES.md).

**Имена:**

- объекты: `<id>-<s|l>-<main|background>.svg`;
- плоскости: `plane-<lavender|peach|mint>-<s|l>.svg`.

**Манифест.** Плагин `tools/vite-plugin-forma-assets.ts` при dev и build сканирует папку тем же кодом, что работает в браузере, и отдаёт модуль `virtual:forma-assets`: `viewBox`, реальные границы, цвета и предупреждения по каждому файлу.

**Отсутствующий вариант** заменяется ближайшим существующим: та же разновидность с другой детализацией, затем другая разновидность. Мотив без файлов не появляется нигде.

**Загрузка.** SVG загружаются только по именам из манифеста, с того же origin, и проходят белый список элементов и атрибутов.

## Архитектура

```
src/
  domain/      types.ts — общие контракты; motifs.ts — названия и описания мотивов
  svg/         xml-парсер, санитайзер, геометрия путей и трансформаций, границы, шаблоны экземпляров
  assets/      manifest (virtual:forma-assets), availability (имена, фолбэки), loader (fetch + кэш)
  palette/     OKLab, роли и исходные палитры Figma, резолвер цветов, валидация JSON
  semantics/   нормализация, стеммер, словарь и темы, analyzeTitle, parseNames, interpreter
  layout/      зоны форматов, варианты раскладки, compose(), фоновый предмет (scenery.ts)
  doc/         модель документа, валидация, редьюсер истории, черновик, демо-пресеты
  export/      render.ts — общие функции превью и экспорта, buildExportSvg
  ui/          панели React; state/useEditor.ts — единая точка состояния (EditorApi)
  styles/      tokens.css — дизайн-токены и общие примитивы
tools/         Vite-плагин и сканер ассетов (Node)
```

**Поток данных:**

```
задание → analyzeTitle / parseNames → мотивы
        → resolveAsset (фолбэк) → compose (зоны, ярусы, общий масштаб)
        → DocState (история, черновик)
        → renderLayer / renderPlane ─┬─ превью (React, dangerouslySetInnerHTML только для проверенных шаблонов)
                                     └─ buildExportSvg (тот же код)
```

**Принципы:**

- Вся логика (семантика, геометрия, раскладка, перекраска, экспорт, валидация) — чистые функции без DOM. Поэтому она покрыта тестами в Node и работает одинаково в браузере и в Vite-плагине.
- Во время перетаскивания меняется только атрибут `transform`. Разметка экземпляра мемоизирована по файлу, id группы и палитре.
- Зависимостей в рантайме минимум: React и два шрифта (Onest, Literata) с кириллицей. Шрифты встроены в сборку. Единственные сетевые запросы — `/api/health` и `/api/interpret` к собственному серверу.

### Подбор с ИИ

- `server/index.mjs` — сервер на стандартной библиотеке Node без зависимостей. Раздаёт `dist/` и принимает `POST /api/interpret`; `GET /api/health` сообщает, настроена ли модель.
- `server/interpret.mjs` — чистые функции: проверка запроса, промпт, разбор ответа (id вне каталога отбрасываются).
- `src/semantics/llm.ts` — клиент: `applyLlmPick` сливает ответ с анализом словаря; выбранный моделью фон хранится в документе (`scenery`).
- Переменные окружения: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_API_KEY_HEADER` (пусто = `Authorization: Bearer`), `FORMA_LLM_MODEL`, `FORMA_LLM_FALLBACK_MODEL` (резервная). Читаются из окружения или из `.env.local`, который не попадает в git.
- Защита: тело запроса до 16 КБ, заголовок до 300 символов, 20 запросов в минуту с одного адреса, таймаут 8 секунд на модель; при старте сервер прогревает модель.
- Без сервера или без ключа `/api/health` недоступен, и редактор работает на одном словаре.

## Ограничения и известные пробелы

- **Словарь семантики** ручной: около 10 тем и несколько сотен ключей. Без ИИ редкие заголовки уходят в нейтральную композицию с подсказкой. С ИИ их толкует модель, но ответ зависит от неё и может меняться от запуска к запуску.
- **Отдельного масштаба объекта нет:** общий масштаб сохраняет пропорции рисунков Figma. Размер всей композиции зависит от формата и компоновки.
- **Зона заголовка** — направляющая превью. Сам текст в SVG не экспортируется: его набирают в макете публикации.
- **Раскладка** оценивает перекрытия по габаритным прямоугольникам. У изометрических рисунков пустые углы, поэтому оценка консервативна.
- **Мобильная версия:** на узком экране редактор складывается в одну колонку. Основные кнопки, действия со слоями и кнопки в диалогах увеличены для касания. Для точной работы с мелкими объектами удобнее мышь или трекпад.
- **Смена формата или компоновки** раскладывает объекты заново. Ручные сдвиги и повороты при этом теряются, но скрытые слои остаются скрытыми, а шаг можно отменить. Стрелки в группах «Формат» и «Компоновка» переключают значение сразу, и каждый шаг попадает в историю.
- **Линии плоскости** — часть рисунка Figma. В режиме «С заголовком» они могут проходить через зону заголовка, автоматического отзеркаливания плоскости нет.
- **Черновик** один на браузер, синхронизации между устройствами нет. Нечитаемый черновик не стирается, а сохраняется под ключом `forma:draft:v1:backup`.
